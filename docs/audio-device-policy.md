# 音频设备与回声策略 · 2026-10-18

## 已落地

设备生命周期保护：每次启动重新枚举核对端点，活动测试期间每 2 秒复查。活动端点消失或混音格式改变，或原生流报告故障时，两路测试一并停止并要求重新检测，不自动重开麦克风。当前用主进程轮询，不是原生热插拔通知，尚未做真机拔插验收。

测试开始后面板固定该轮输入/输出设备对；系统默认变化不会迁移当前流或切换另一侧测试的目标。运行期间后台复查不等于允许用户手动切换设备；空闲时仍可手动刷新，重新检测不自动恢复测试。

音频面板新增显式 AEC 开/关选择，默认关闭，影响下一次麦克风测试。普通引擎 0.3.1 仅支持旁路，开启选项禁用；实验引擎 0.4.1-aec3-experimental 默认也旁路，用户选择开启才使用原 Default AEC3（没有推广低激励或 mask 候选）。关闭 AEC 是绕过算法，不是将其输出静音，不代表共享模式已成为硬件 RAW。

开始采集前主进程发送 `processing.set` 并核对返回的实际 mode；不支持开关的旧实验引擎被拒绝，防止界面声称关闭但实际上仍处理。原生层仅允许采集、播放均停止时切换，join 两个工作线程后重建 AEC、清空参考和统计；运行时不热切换。开关不控制独立降噪，当前降噪尚未实现。

面板提供“记住此输入／输出设备对”按钮。只有明确点击才保存到 Electron userData 下的 `audio-preferences.json`，键为实际输入 ID + 输出 ID；不按名称匹配，不保存 `default` 占位值，不保存账号或音频。新设备对默认关闭，重新打开面板/切换设备时读取各自记录，未保存的修改不会跨面板保留。

“跟随系统默认”按最近枚举的唯一默认端点解析，开始测试时传入解析后的实际 ID，从而不会在启动时悄悄改用另一个默认设备。系统默认端点变化后需停止测试并刷新，当前测试不自动迁移；运行中禁止刷新和更换设备。没有唯一可用的输入/输出组合时不能保存或开始新采集；不按设备名称自动启停。

读取期间不允许启动新采集；旧设备对的异步读取结果不能覆盖新选择。偏好文件校验版本/字段/重复记录，限制 256 对和 1 MiB；写临时文件后替换。读取失败保持 AEC 关闭，损坏文件不静默覆盖。普通引擎读到保存的 true 仍保持关闭，UI 提示且不会自动改写记录；只有用户明确保存关闭才更新该值。尚未完成热插拔实时通知与跨进程并发编辑支持。

原生枚举通过 Windows `PKEY_AudioEndpoint_FormFactor` 读取驱动报告的耳机、耳麦、扬声器、听筒、麦克风、线路、数字或显示器端点类型。缺失或不支持的值为 unknown。协议兼容旧引擎缺失该字段的情况。

音频面板按所选**输出**设备提供路径提示，不按名称猜测，不以麦克风类型决定是否耳机。正在播放时按引擎实际 deviceId 判断；系统默认项使用最近枚举的默认端点，系统切换后需要刷新。此分类是提示，不控制 DSP，也不证明输入输出属于同一个硬件。

## 接入实时 AEC 时必须遵守

- 外放：默认启用经验证的 AEC，以实际发送到该输出的最终 PCM 为参考。不能拿麦克风监听信号或错误输出设备的数据作参考。
- 耳机/耳麦：以保真人声为优先，不能只因驱动标注耳机就假定无回声。开放式耳机、漏音、声卡回送仍需验证；已提供明确的 AEC 开/关覆盖及用户触发的设备对保存，不代表算法验收通过。
- 未知、线路、显示器或数字输出：末端设备不确定，不自动按耳机关闭 AEC。
- 只有验证过的稳定无回声路径才考虑自动旁路，避免依据短暂静音来反复开关算法。关闭 AEC 不能顺带关闭独立的降噪配置；耳机麦克风也可能收到键盘、风扇等噪声。
- 输入、输出、采样格式、系统路由改变要停止旧链并重建；不能复用旧设备的延迟或滤波状态。音量/路径变化需要适应；未来参考队列丢帧和时钟漂移也须有恢复策略。以上实时生命周期仍待实现。
- 硬件/驱动可能已经处理过声音；共享模式不是 RAW，不宣称取得设备未处理原始音频，也不盲目叠加多重强抑制。

## 蓝牙与音质

经典蓝牙的 A2DP 与 HFP 有不同播放/收音能力；开启耳机麦克风可能切换通话模式。LE Audio 需要另行探测，不能套用经典蓝牙限制。当前只读取端点类型，**尚未识别蓝牙连接、活动 profile、编解码器或物理设备配对**。把共享流转换成 48 kHz 不会恢复原先不存在的高频带宽。

参考：[微软端点类型文档](https://learn.microsoft.com/en-us/windows/win32/coreaudio/pkey-audioendpoint-formfactor)、[微软蓝牙 Classic Audio 文档](https://learn.microsoft.com/en-us/windows-hardware/drivers/bluetooth/bluetooth-classic-audio)。

## 本轮离线验收

2026-10-18 更新：下述旧噪声基线通过不能代替真实录音负例。用户录音的零回声模型中，默认 AEC3 与低激励候选均误抑制近端约 10.78 dB；近端 mask 诊断仍约 10.53 dB，失败。参见 `speech-result-2026-10-18.md`。因此 AEC 不能只凭旧合成耳机场景通过就默认用于耳机；现有显式覆盖不代表算法修复，不能自动按耳机名称绕过 AEC。

新增“有远端播放但完全无声学回声”的理想耳机场景：麦克风收到独立的近端合成信号。稳态能量衰减 0.14492 dB，补偿固定算法延迟后相关系数 0.959874（门槛 >0.9），每 10 ms 块 P95 206.2 μs。近端单独输入同样通过；原回声衰减仍为 66.6233 dB。

这些是低通随机信号测试，不是实际耳机测量，不证明语音主观质量、真实双讲或漏音处理。当前客户端依旧 bypass，AEC/NS/RTC 未启用。
