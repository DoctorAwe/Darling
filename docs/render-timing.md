# 播放参考时序 · 2026-10-16

原先发布的是提交时刻，而非端点播放时刻，且启动前就能被采集线程消费。本轮改为以下流程：

1. 生成最终应用增益后的 PCM，组装 480 样本块，记录该块首样本在 48 kHz 客户端流中的索引。
2. ReleaseBuffer 成功后进入播放线程私有的有界暂存队列，不直接发布给采集线程。
3. Start 后获取 IAudioClock 的 position、frequency 与 100 ns QPC。完整块已播放时，用 `qpc + (首样本索引 / 48000 - position / frequency) * 10000000` 估算首样本端点播放时间，发布到 SPSC 参考队列。
4. 采集端只消费时间不晚于当前采集块的参考，每个采集块最多追赶两个有效参考块。丢弃旧会话与过期帧，不做无限追赶。

时钟频率/位置单位遵循 [Microsoft IAudioClock::GetPosition](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudioclock-getposition)；不把位置误认为客户端样本数。零位置尚未建立播放锚点，S_FALSE 不作为可靠时钟测量；非法频率、回退、溢出会终止诊断。结束时等待 padding 清空及暂存参考发布完毕，仍保留 4 秒诊断超时。

这只是端点时钟估算，不是麦克风收到回声的时刻。没有叠加驱动报告的最大延迟来冒充实际声学延迟；尚未实现漂移补偿、捕获延迟缓冲或实时 AEC 参考饥饿恢复。完整块播放后发布的策略偏保守，会增加块级等待；接入 AEC 前应联合测试调度与算法，而不能仅凭参考块计数判定消回声有效。

真机短测：100 个参考块全部消费，dropped/stale 为 0，正常停止；采集 141 块。采集仍 bypass，本次没有记录/上传音频，也没有测量回声衰减。
