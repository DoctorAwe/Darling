# RTC 真实设备诊断

这是开发诊断入口，不是已验收的正式通话。先降低系统输出音量；启动客户端不会自动开启音频。

在项目根目录启动（默认 dva）：

```powershell
node scripts/start-device-diagnostic.mjs
```

使用 mercy：

```powershell
node scripts/start-device-diagnostic.mjs --user=mercy
```

仅检查文件，不启动应用或登录：

```powershell
node scripts/start-device-diagnostic.mjs --check
```

启动器使用 `.local/<用户名>.config.json` 自动登录，可能替换该账号已登录的客户端；诊断缓存独立存放。路径和配置只设置在子进程环境中，不改系统环境、不安装 SDK、不复制或输出密码。

1. 打开“音频设备”，点击“检测 / 刷新设备”。检测不会录音。
2. 选择正确的输入、输出设备，核对 RTC 测试区显示的实际名称。
3. 明确选择“耳机”或“扬声器”；耳机关闭 AEC，扬声器开启 AEC。降噪独立选择，首次可关闭用于基线。
4. 降低系统音量，勾选本次录音/播放确认，点击“开始 15 秒 RTC 设备测试”。
5. 会播放连续 1200Hz 测试音，同时采集麦克风，经本机 Opus 链路送至虚拟接收端；不会把自己的声音回放，不保存音频或上传服务器。
6. 随时点击“立即停止 RTC 测试”，或关闭音频面板。达到 15 秒自动停止；驱动阻塞时最多额外等待约 2 秒后强制结束原生进程。

请反馈：输入/输出名称、所选模式、是否听到测试音、状态区最终提示、停止后测试音是否消失。无需提供账号密码。

## 检查麦克风输入链路

重启更新后的客户端，在 15 秒测试中先保持安静约 3 秒，再正常讲话几秒。观察“麦克风输入链路”区域：发送/对端接收包数应持续增长，对端解码 RMS、峰值应能体现活动。可反馈讲话前后大致电平，以及停止后保留的发送包数、接收包数、最大峰值；不需要上传录音。

页面每秒采样一次，瞬时电平取最近 10ms 块，可能错过很短的发声；本次最大峰值会保留。计数增长不等于收到人声，静音也可能发送数据，外放测试音漏入麦克风也可能产生电平。显示“暂无”表示还没有该统计，不等同于零或静音。

“本机 RTC 已连接”只代表连接建立，不代表麦克风采集正确、实际播放正确或 AEC/降噪音质达标。RAW、系统驱动处理、蓝牙通话模式、热拔插和真实双机通话仍需后续验收。
