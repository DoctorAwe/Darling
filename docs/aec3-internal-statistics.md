# AEC3 内部状态统计（2026-10-21）

状态：只在离线命令显式 `--trace-internals` 时开启；默认关闭，不改变抑制增益，不保存 PCM，不接入 RTC 或稳定版。

## 实现

`scripts/apply-aec3-diagnostics.mjs` 将项目内的 `aec3_diagnostics.h` 复制到固定 WebRTC 工作树，并在官方 `echo_remover.cc` 的 `GetGain` 后安装一个幂等钩子。上游锚点变化时脚本直接失败，不静默插入错误位置。实验构建脚本会先执行它。

统计 AEC3 16 kHz 低频带频点 1–15：

- dominant-nearend 帧比例；
- usable-linear 帧比例；
- 窗口累计残余回声功率／累计近端功率；
- 低频平均增益及 P10/P50/P90；
- dominant 与普通状态下的平均增益。

第一版逐块计算残余／近端比，在近端接近零时产生无意义极大值；已废弃。当前报告采用窗口累计功率比。纯远端场景近端分母仍接近零，因此其比值只表示强回声主导，不用于跨场景定量排名。

复现：

```powershell
node scripts/apply-aec3-diagnostics.mjs
# 构建 darling_aec_chain_test 后：
node scripts/diagnose-aec3-internals.mjs `
  .local/aec-comparison-1792564640078 `
  .local/aec-comparison-1792564671673
```

有效报告：`.local/aec3-internals-1792565084930/report.json`。前一个 `1792565035416` 报告的功率比口径无效，不引用。

## 核心结果

| 场景 | 段 | 默认保护比例 | 组合候选保护比例 | 默认保护态/非保护态平均增益 | 候选保护态/非保护态平均增益 |
|---|---|---:|---:|---:|---:|
| 模拟耳机无回声 | 前 | 60.7% | 71.5% | 0.777 / 0.202 | 0.817 / 0.171 |
| 模拟耳机无回声 | 后 | 76.7% | 82.6% | 0.906 / 0.264 | 0.934 / 0.167 |
| 双讲 | 前 | 72.2% | 78.1% | 0.515 / 0.116 | 0.598 / 0.126 |
| 双讲 | 后 | 72.7% | 78.8% | 0.605 / 0.040 | 0.681 / 0.032 |
| 弱双讲 | 前 | 63.8% | 73.2% | 0.490 / 0.111 | 0.551 / 0.121 |
| 弱双讲 | 后 | 65.5% | 73.7% | 0.574 / 0.049 | 0.643 / 0.040 |

默认双讲窗口有约 27–36% 帧不在 dominant 保护状态；这些帧的平均增益明显更低。组合候选一方面把保护覆盖提高约 6–10 个百分点，另一方面提高保护态增益，因此前述输出改善具有内部状态证据支持。

风险也被直接确认：后半段纯远端场景中，默认 dominant=0，组合候选为 4.8%。这些误保护帧的平均增益约 0.020，未明显释放回声，因此整窗纯回声衰减近似不变；但这不保证其他回声路径也安全，且完整链路路径变化指标已出现退化。

有界与无界残余功率在双讲窗口差异明显，但仅改 bounded-residual 的输出反而变差，说明不能通过简单切换谱边界解决问题。模拟耳机场景 usable-linear 比例在两段分别约 51.8% 和 17.8%，值得后续单独研究为何无实际回声时线性估计可用性变化大。

## 当前结论

已从输出推断推进到内部证据：检测覆盖不足确实存在，保护态与非保护态抑制强度差距很大；组合候选改善机制成立。但其误触发风险和弱双讲失败仍阻止推广。

下一步应保留 nearend-mask，针对检测器做更保守的单变量扫描：优先调整触发/保持时序，而不是同时放宽 ENR、SNR、触发与保持四项；验收必须包含纯远端误触发率、路径变化回声和两段弱双讲。
